## What Went Well

1. **The short loop worked.** The cadence was story → deploy → live check → next story. Live checks seeded the next story directly: 7.21 → 7.24, 7.26 → 7.27 → 7.28. Story specs stayed short (7.28's is about 60 lines).
2. **Careful production data work.** 7.13 and 7.16 each ran a dry run, waited for Sandy's approval and noted a restore point before applying.
3. **Review caught real defects when it ran in full.** 7.21: double Save, delete confirm dismissible by Escape mid-delete, focus not returning to the opener. 7.20: a duplicate history entry. 7.10: renamed-song resolution. 7.15: a wake lock leak.
4. **Boundaries held.** web ↔ api stayed HTTP-only. The back end changed only where a story needed it.
5. **Deferred work got picked up.** 7.23 was built from the deferred list. `deferred-work.md` had 17 stale items struck after the reset.
6. **The token-saving rules held.** No screenshot tooling once 7.2 was dropped. Sandy's own look on phone and laptop replaced it.

## Challenges and Lessons

1. **Later stories reversed earlier decisions, at Sandy's choice:** 7.29 reversed 7.8's "no Edit in a gig", 7.28 reversed 7.26's "Strut" rule, 7.20 removed 7.1's Home page and 7.19 replaced 7.14's Previous/Next. *Lesson:* this is the iterative model working as intended, not churn. It was cheap because each story was small and the reasons were written in the Dev Notes.
2. **One story introduced a data bug.** In 7.9, changing a gig's date duplicated the gig, because setlists were keyed by date. 7.13 fixed it with a migration. *Lesson (inference):* keys built from editable fields need a question in the spec: "what happens when this field changes?"
3. **Live checks found faults the tests missed.** In 7.19 the play bar was 44px instead of 64px because tailwind-merge dropped a class, and the phone showed a strip below it. Sheets appeared without sliding (7.21 → 7.24). iPhone date inputs overflowed the sheet (52b4be8). *Lesson:* the live check earns its place; layout faults on iPhone need eyes, not just jsdom.
4. **Test gigs trip the deploy blackout.** The 2026-10-19 proposal (§2.4) predicted it: three stories in a row needed deploy-force because of a "Test" gig dated 2026-10-29. *Lesson:* either clean up test gigs or let the blackout ignore them. That's Sandy's call (Q2).
5. **Review depth fell over the epic.** 7.1 had the full three-layer review. From about 7.11, most reviews were lightweight or inline, and 7.28 has none recorded. The full reviews (7.20, 7.21) found the most. *(inference)* Lightweight reviews suit small presentational stories, but stories touching state, history or data have repaid the full review.
6. **Some fixes landed outside their story commit.** Fixes to 7.19, a 7.25 follow-up, a flaky 7.21 test that failed a 7.22 deploy, and the deploy-force output delimiter. This is minor, but it stretches the one-commit-per-story convention.
7. **One permission slip (7.13).** The agent sent `git push` and the migration `--apply` in the same step. The apply was blocked and Sandy ran it. *Lesson:* production-data commands go in their own step, after Sandy's go-ahead.
